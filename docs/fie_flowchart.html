Failure Intelligence Engine · Request Lifecycle

How Every Request Is Processed

Every prompt passes through 12 security layers before reaching your model. Every output is monitored for hallucinations by a shadow ensemble and a three-agent AI jury. This is what happens, in order.

v1.13.0 12 detection layers 3 shadow models DiagnosticJury: 3 agents XGBoost FSV classifier
TL;DR The 30-second version

Think of FIE as a security checkpoint wrapped around your AI model. Nothing reaches your model until it's been screened, and nothing the model says goes unchecked. There are just three moments to understand — everything below is the detail behind them.

🛡️ Before — screen the prompt
12 detectors check every incoming prompt in parallel (under 20ms). Clear attacks — jailbreaks, prompt injection, smuggled instructions — are blocked before your model runs.
🤖 During — your model answers
Safe prompts pass straight through to your own LLM. The answer returns to the user at full speed — FIE adds no delay on the path the user feels.
🔬 After — check the answer
In the background, 3 shadow models and a 3-agent jury catch hallucinations. The result is VALIDATED, CORRECTED, or BLOCKED — and the system learns from every confirmed case.

6
LLM Execution & Output Scanning
The user's model runs. The response is returned immediately. Scanning happens asynchronously — zero added latency for the user
async scan
🤖 LLM Call — Your Model
The user's chosen LLM generates its response. FIE does not interfere with this call — the response is returned to the user at full speed (typically 500–2000ms).

FIE wraps the response and triggers the monitoring pipeline on a background daemon thread.
🔍 Output Scanning ASYNC — zero added latency
Non-streaming responses: scan_output_async() on daemon thread. Checks for policy echo (0.92), system prompt leakage (0.88), harmful output (0.90).

Streaming responses: stream_guard / astream_guard buffers 400 chars, scans, then either passes through or yields a refusal and stops the stream.
📛 POLICY_ECHO — threshold 0.92 🔓 SYS_PROMPT_LEAK — threshold 0.88 ⚠️ HARMFUL_OUTPUT — threshold 0.90 Flagged outputs → Feedback Store → human review queue
FastAPI routes to LangGraph

📊 Failure Signal Vector (FSV)
Entropy — response variance across shadow outputs
Consistency — self-consistency across rephrased prompts
Ensemble disagreement — inter-model pairwise cosine distance
Embedding distance — semantic distance between primary and shadow answers

8
DiagnosticJury — 3 Specialist Agents in Parallel
Three AI agents independently analyze the failure mode with full FSV context. Their verdicts are merged by weighted vote.
parallel agents
⚔️ Adversarial Specialist
Re-evaluates all 12 detection layer signals with full context and FSV snapshot. Runs PAIR v4 again in context-aware mode. Checks for structural attack patterns the pre-flight guard may have missed at lower confidence.
Verdicts: ADVERSARIAL_ATTACK · PROMPT_INJECTION · JAILBREAK · CLEAR
📝 Linguistic Auditor
Analyzes grammar, coherence, and linguistic quality of the model's response. Detects hedge phrases ("I think", "I'm not sure"), refusal signals, and confidence calibration mismatches.
Verdicts: LINGUISTIC_DEGRADATION · HEDGED_RESPONSE · REFUSAL · CLEAR
🎓 Domain Critic
Checks for factual hallucination using 5 sub-layers: contradiction signal, self-contradiction between primary/shadow, hedge detection, temporal knowledge cutoff, and external Wikipedia/Serper verification.
Verdicts: FACTUAL_HALLUCINATION · TEMPORAL_CUTOFF · KNOWLEDGE_BOUNDARY · CLEAR
⚖️
Jury Verdict — Weighted Merge
Three verdicts are merged using weights based on failure_type from XGBoost. Confidence scores are combined. A requires_human_review flag is set when agents disagree or confidence is near-threshold.
9
Explainability Layer
Every decision produces a human-readable explanation with SHAP attributions, evidence, and a full decision trace
🔍 Internal Mode (operators / audit)
Full SHAP values for every FSV feature · Raw matched text from detection layers · Specific threshold values · All layer scores · Full jury reasoning chains · Decision trace with ordered steps · Uncertainty notes for near-threshold calls
👤 External Mode (end users)
Outcome labels only · No threshold values (hides detection mechanics from attackers) · Only safe_to_expose=True signals · Human-readable explanation of why the request was blocked or flagged · No raw matched text
Explanation quality score = 0.25×jury + 0.20×evidence + 0.20×signals + 0.20×fix + 0.15×source − penalties
10
Final Outcome — One of Three Results
Every request ends in exactly one outcome, with full traceability back to every detection signal
✅
VALIDATED
The primary model's response was confirmed correct by the shadow ensemble and jury. No hallucination or attack detected.
Primary model trusted · Response returned as-is
🔧
CORRECTED
Hallucination detected. The primary model's answer diverges from shadow consensus. The shadow majority answer is returned instead.
Shadow consensus replaces primary output
🚫
BLOCKED
An adversarial attack was detected — either in the pre-flight guard (before LLM ran) or confirmed by the jury after analysis.
Refusal returned · Event logged for review
